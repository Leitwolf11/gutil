# Linux x86-64 adjacent-record filtering comparison

Compare gutil commit `f75547340ca3582830fc061489c703abdff83ce9` with
GNU Coreutils uniq 9.12. Each workload reads a 72 MiB regular file.
The file repeats a group of two identical records, a singleton, and
a group of three identical records. Each record is 96 bytes including
its newline. The three modes keep the first record, print counts with
`-c`, or print all repeated records with `--all-repeated=separate`.

| Item | Environment |
| --- | --- |
| CPU | Intel Core i5-3210M at 2.50 GHz, 4 logical CPUs, pinned to CPU 3 |
| RAM | 7.61 GiB visible to Linux |
| OS | Arch Linux x86-64, kernel 7.3.4-zen2-2-zen |
| Compiler | rustc 1.100.0 with LLVM 23.1.5, default release profile |
| Filesystems | ext4 executables, tmpfs input |
| Reference | GNU Coreutils uniq 9.12 |

The harness compares SHA-256 of the complete output outside timing. Three
warmup rounds precede 16 measured rounds in seeded interleaved order.
Timed invocations include startup and exit and send stdout to the null
device. The harness verifies successful exit and absent diagnostics.
Both executables use `LC_ALL=C` and `TZ=UTC`. gutil uses
`--no-config --progress=never --jobs=1`.

| Workload | gutil median (ms) | GNU median (ms) | Paired reduction vs. GNU (median and IQR) |
| --- | ---: | ---: | ---: |
| default | 64.16 | 224.59 | 71.6% [69.7%, 72.0%] |
| count | 104.83 | 232.35 | 54.6% [51.1%, 55.8%] |
| duplicates | 66.71 | 235.97 | 71.7% [70.8%, 72.5%] |

gutil had the lower median in all three workloads on this host. The
fixture uses warm regular-file input with fixed-size ASCII records.
Short commands, skipped fields, and multibyte comparison are outside
the scope of this throughput measurement.

```sh
cargo build --locked --release -p gutil
taskset -c 3 python3 benchmarks/uniq_bench.py target/release/gutil --gnu /usr/bin/uniq
```
