# Linux x86-64 shell and system benchmark

Measured on November 17, 2026, in Europe/Istanbul. The Criterion run
compares gutil 0.11.0 at commit `47147d988c73030935b427577f195674d334dae2`
with GNU Coreutils 9.12.

## Machine and tools

| Item | Recorded value |
| --- | --- |
| CPU | Intel Core i5-3210M at 2.50 GHz, 2 physical cores, 4 logical CPUs |
| Available CPUs | All 4 logical CPUs, without isolation |
| Frequency policy | `intel_cpufreq` driver and `schedutil` governor |
| RAM | 7.61 GiB visible to Linux |
| Operating system | Arch Linux, x86-64 |
| Kernel | `7.3.4-zen2-2-zen` |
| Filesystems | ext4 for the checkout and executable, anonymous pipes for `yes` |
| Rust toolchain | rustc 1.100.0 and Cargo 1.100.0, host `x86_64-unknown-linux-gnu` |
| Harness | Criterion 0.8.2, optimized Cargo bench profile |

## Workload

Each timed iteration starts one process. Finite commands discard stdout,
and the harness checks output bytes and exit status in a preceding run.
The `yes` consumer drains exactly 16 MiB, closes the pipe, then waits for
the writer. The harness verifies an 8,192-byte prefix before timing.
Both implementations use the C locale, UTC, and an unset
`POSIXLY_CORRECT`. gutil uses `--no-config --progress=never`. For the
`nproc` invocation, both receive `OMP_NUM_THREADS=4` and
`OMP_THREAD_LIMIT=3`. The `printenv` values are `alpha` and a two-line
value consisting of `beta` and `gamma`.

```sh
TMPDIR=/tmp GNU_COREUTILS_DIR=/usr/bin cargo bench --locked -p gutil --bench shell -- --noplot
```

Criterion uses 10 samples, a 400 ms warmup, and one second per finite
command or two seconds for the pipe workload.

## Results

Elapsed-time point estimates and 95% confidence intervals are in milliseconds.

| Invocation | gutil | GNU |
| --- | ---: | ---: |
| `true` | 1.810 [1.666–1.899] | 0.852 [0.829–0.883] |
| `false` | 1.656 [1.579–1.714] | 0.815 [0.782–0.881] |
| `echo -e 'hello\tworld' '\x21'` | 1.640 [1.577–1.714] | 0.849 [0.798–0.903] |
| `printenv -0 GUTIL_BENCH_A GUTIL_BENCH_B` | 1.730 [1.659–1.893] | 0.830 [0.811–0.863] |
| `nproc --ignore=1` | 1.785 [1.712–1.897] | 0.884 [0.851–0.921] |
| `sleep 0.002s` | 5.396 [5.292–5.563] | 3.364 [3.319–3.436] |
| `yes`, first 16 MiB through a pipe | 7.598 [7.357–7.810] | 4.204 [4.144–4.247] |

GNU had lower elapsed-time intervals for these invocations. The short
commands include process startup. The sleep measurement also includes
timer granularity and the requested wait.

## Paired Linux pipe test

The optimized gutil binary at commit `fc6317b598546cd8381425295bf9834464f676fb`
uses `sendfile` to reuse pages containing whole output lines. The baseline
uses buffered writes. A Python 3 consumer used a reusable 64 KiB buffer
and `readinto` to drain exactly 16 MiB before closing the pipe. Timing
included process startup and exit. Each round shuffled the three variants
with a fixed seed of 42. Four warmup rounds preceded 30 measured rounds.

| Variant | Median elapsed time | Interquartile range |
| --- | ---: | ---: |
| Baseline gutil | 7.640 ms | 7.189–8.235 ms |
| gutil with `sendfile` | 5.495 ms | 4.647–6.316 ms |
| GNU Coreutils 9.12 | 4.328 ms | 3.965–4.643 ms |

The optimized binary finished sooner than the baseline in all 30 rounds.
The median of the paired reductions was 28.3%, with an interquartile range
of 23.1–32.1%. GNU had the lowest median in this workload.
