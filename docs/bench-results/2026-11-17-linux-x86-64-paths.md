# Linux x86-64 path benchmark

Measured on November 17, 2026, in Europe/Istanbul. This run compares gutil
0.9.0 at commit `8e535335afa3ef4005509b58e583971f56bcc44c` with GNU Coreutils 9.12.

## Machine and tools

| Item | Recorded value |
| --- | --- |
| CPU | Intel Core i5-3210M at 2.50 GHz, 2 physical cores, 4 logical CPUs |
| Available CPUs | All 4 logical CPUs, without isolation |
| Frequency policy | `intel_cpufreq` driver and `schedutil` governor |
| RAM | 7.61 GiB visible to Linux |
| Operating system | Arch Linux, x86-64 |
| Kernel | `7.3.4-zen2-2-zen` |
| Filesystems | ext4 for the checkout and executable, tmpfs for the fixture under `/tmp` |
| Rust toolchain | rustc 1.100.0 and Cargo 1.100.0, host `x86_64-unknown-linux-gnu` |
| Harness | Criterion 0.8.2, optimized Cargo bench profile |

## Workload

The harness creates 512 regular files from `inputs/item-0000.txt` through
`inputs/item-0511.txt` and one relative symbolic link per file. Each process
receives all 512 operands in order. Both implementations use the same
fixture, the C locale, UTC, and an unset `POSIXLY_CORRECT`. gutil also uses
`--no-config --progress=never`. The harness checks the full output of each
pair before timing. Each timed iteration starts one process, discards its
stdout, and waits for it to exit.

```sh
TMPDIR=/tmp GNU_COREUTILS_DIR=/usr/bin cargo bench --locked -p gutil --bench paths -- --noplot
```

Criterion uses 10 samples, a 400 ms warmup, and a one-second measurement
target for each invocation. Files and links remain resident in tmpfs.

## Results

Point estimates and 95% confidence intervals are in milliseconds.

| Workload | gutil, one worker | gutil, four workers | GNU |
| --- | ---: | ---: | ---: |
| `basename -zs.txt` over file names | 2.013 [1.917–2.095] | | 1.801 [1.447–2.409] |
| `dirname -z` over file names | 2.778 [2.496–3.044] | | 1.712 [1.456–1.850] |
| `realpath -e -z` over existing files | 4.274 [4.023–4.524] | 2.994 [2.916–3.178] | 2.687 [2.503–2.797] |
| `readlink -z` over symbolic links | 2.569 [2.452–2.685] | 2.790 [2.502–3.028] | 1.608 [1.526–1.702] |

Four workers reduced gutil's `realpath` elapsed-time point estimate by
29.9% compared with one worker. GNU had a lower interval in that workload.
The gutil intervals for `readlink` overlapped across worker counts, and
GNU's interval was lower than either. For the lexical commands, the
`basename` intervals overlapped and GNU had a lower `dirname` interval.
