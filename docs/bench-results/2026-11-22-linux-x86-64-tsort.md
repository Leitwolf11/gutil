# Linux x86-64 topological ordering

Compare release build gutil `7f46ae6` with GNU Coreutils 9.12 `tsort` on
four acyclic graphs of 120,000 names. The workloads distinguish narrow
dependency depth, wide successor lists, independent roots, and a
branching tree.

| Item | Environment |
| --- | --- |
| CPU | Intel Core i5-3210M at 2.50 GHz, 2 cores and 4 logical CPUs |
| Affinity | Harness and child processes pinned to logical CPU 3 |
| Memory | 7.61 GiB visible to Linux |
| System | Arch Linux x86-64, kernel 7.3.4-zen2-2-zen |
| Toolchain | rustc 1.100.0 with LLVM 23.1.5, default release profile |
| Storage | Executables on ext4, input and output on tmpfs |

Each workload reads a warm regular file of approximately 3.12 MB and
writes another regular file. Input names and relation order are seeded.
The independent-root case uses 120,000 self-pairs. Each other case uses
119,999 edges. Both utilities use the C locale. gutil uses
`--no-config --progress=never --jobs=1`.

Four warmups precede 12 measured rounds with interleaved executable order.
Timing includes startup, reading, graph construction, ordering, writing,
and exit. Every run must exit successfully, produce empty stderr, and
match the full stdout SHA-256. Hashing occurs outside timing.

| Workload | gutil median (ms) | GNU median (ms) | Paired reduction vs. GNU, median [IQR] |
| --- | ---: | ---: | ---: |
| Chain | 63.06 | 165.43 | 60.8% [59.4%, 62.7%] |
| Fan-out | 63.19 | 149.16 | 57.4% [55.8%, 60.2%] |
| Independent roots | 130.30 | 165.87 | 21.3% [17.2%, 24.2%] |
| Binary tree | 115.45 | 274.87 | 58.6% [56.9%, 62.5%] |

The paired median elapsed times were 21–61% lower than GNU's in these
warm acyclic workloads on the recorded Linux host.

[Raw observations and executable hashes](2026-11-22-linux-x86-64-tsort.json)

```sh
cargo build --locked --release -p gutil --bin gutil
TMPDIR=/dev/shm taskset -c 3 python3 benchmarks/tsort_bench.py target/release/gutil \
  --gnu /usr/bin/tsort
```
