# Linux x86-64 mounted filesystem benchmark

Measured on November 17, 2026, in Europe/Istanbul. Criterion compared gutil
0.12.0 at commit `7c9a35bd6c76b445edca0016f51de9e460785ac8` with GNU
Coreutils 9.12 and duf 0.9.1.

## Machine and tools

| Item | Recorded value |
| --- | --- |
| CPU | Intel Core i5-3210M at 2.50 GHz, 2 physical cores, 4 logical CPUs |
| Available CPUs | All 4 logical CPUs, without isolation |
| Frequency policy | `intel_cpufreq` driver and `schedutil` governor |
| RAM | 7.61 GiB visible to Linux |
| Operating system | Arch Linux, x86-64 |
| Kernel | `7.3.4-zen2-2-zen` |
| Filesystems | ext4 for the checkout and executable, tmpfs for the file operand |
| Mount inventory | 27 mount entries with 26 distinct mount paths |
| Rust toolchain | rustc 1.100.0 and Cargo 1.100.0, host `x86_64-unknown-linux-gnu` |
| Harness | Criterion 0.8.2, optimized Cargo bench profile |

## Workload

The `df` workload prints `--output=source,size,target` for one empty
file called `sample` on the `/tmp` mount. The repeated workload lists
that same operand 512 times in one invocation. Parity checks compare
the three fields of every data row after removing alignment whitespace.

The `duf` workload reports all mounted filesystems with `--all --json`
(gutil) or `-all -json` (upstream). The harness checks the total byte
capacity for each common mount point. Times include program startup and
all queries, and stdout is discarded. The processes use the C locale,
UTC, and default block-size environment settings. gutil runs with
`--no-config --progress=never`.

```sh
TMPDIR=/tmp GNU_COREUTILS_DIR=/usr/bin REFERENCE_DUF=/usr/bin/duf cargo bench --locked -p gutil --bench disk -- --noplot
```

Criterion uses 10 samples, a 400 ms warmup, and a one-second measurement
target per invocation.

## Results

Elapsed-time point estimates and 95% confidence intervals are in milliseconds.

| Workload | gutil | Reference |
| --- | ---: | ---: |
| `df`, one file operand | 2.348 [2.199–2.437] | 1.011 [0.944–1.134] |
| `df`, 512 repeated operands | 4.895 [4.499–5.188] | 4.177 [4.053–4.346] |
| `duf`, JSON inventory | 2.679 [2.665–2.713] | 3.444 [3.407–3.507] |

gutil's `duf` point estimate was 22.2% lower on this inventory.
GNU `df` had lower intervals in both initial file-operand tests.

## Paired repeated-operand test

The optimized gutil binary at commit `603a20230fd32bde9fcaa7718333178bddb38e24`
reuses the mount lookup for identical operands. Both gutil versions still
print all 512 rows. To compare the builds directly, a Python 3 harness
shuffled the original gutil, optimized gutil, and GNU invocations in each
round using a seed of 42. Each measure starts a child, discards stdout,
and waits for exit. Four warmup rounds preceded 30 measured rounds.

| Variant | Median elapsed time | Interquartile range |
| --- | ---: | ---: |
| Baseline gutil | 4.522 ms | 4.428–4.758 ms |
| gutil with lookup reuse | 2.946 ms | 2.923–3.025 ms |
| GNU Coreutils 9.12 | 4.375 ms | 4.314–4.672 ms |

The optimized binary finished sooner than baseline gutil in all 30
paired rounds. The median of the paired reductions was 34.7%, with an
interquartile range of 33.4–38.1%.
