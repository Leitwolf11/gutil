# Linux x86-64 directory creation comparison

Measured on November 19, 2026, in Europe/Istanbul, against GNU Coreutils
`mkdir` 9.12. Baseline `40e3a90` and candidate `3daf85f` both declare gutil
0.16.0 and include the released `tee` implementation. The candidate learns
when to check an existing directory before attempting `mkdir`, using fresh
filesystem metadata for every operand. The baseline always attempts creation
before checking an existing directory.

## Compared workloads

Each process receives either 512 or 4096 directory names, except the depth-four
case, which receives 128 or 1024 paths and creates the same total number of
directories. All processes use `LC_ALL=C`, `TZ=UTC`, and umask 022. Both gutil
executables use `--no-config --progress=never --jobs=1 mkdir`; GNU uses `mkdir`.
Every process has the same single-logical-CPU budget. Directory operations stay
ordered inside one gutil blocking worker.

| Workload | Invocation after the utility name | Expected tree |
| --- | --- | --- |
| `siblings` | `d0000 d0001 ...` | New sibling directories, mode 755 |
| `siblings-mode-750` | `-m750 d0000 d0001 ...` | New sibling directories, mode 750 |
| `parents-depth-four` | `-p p0000/a/b/leaf p0001/a/b/leaf ...` | Four new directories per operand, mode 755 |
| `existing-parents` | `-p d0000 d0001 ...` | Preexisting siblings remain at mode 755 |

Setup, removal of previous fixtures, and complete tree/mode verification are
outside timed intervals. Each timed interval includes process creation,
opening the executable, directory operations, and waiting for exit. The existing
case prepares every directory before timing. Stdout is discarded and stderr is
captured; any nonzero status or diagnostic fails the run.

Four warmup rounds precede 30 recorded rounds per workload. Seed 42 shuffles
all three executables within each round. Measurements use immutable saved
executables. Restoring and rebuilding the candidate after building the baseline
produced bytes identical to the saved candidate on this host. No local build or
test suite ran during the recorded comparisons; ordinary desktop background
activity remained possible.

```sh
# Build each named revision with cargo build --locked --release -p gutil,
# then save its executable at the corresponding immutable path.
taskset -c 3 python3 benchmarks/mkdir.py /tmp/gutil-mkdir-3daf85f \
  --before /tmp/gutil-mkdir-40e3a90 --gnu /usr/bin/mkdir \
  --count 512 --rounds 30 --warmup 4
taskset -c 3 python3 benchmarks/mkdir.py /tmp/gutil-mkdir-3daf85f \
  --before /tmp/gutil-mkdir-40e3a90 --gnu /usr/bin/mkdir \
  --count 4096 --rounds 30 --warmup 4
```

## Elapsed-time results

Values are medians with inclusive interquartile ranges. Paired reductions use
`100 * (reference - candidate) / reference` for each round. Positive reductions
indicate less elapsed time for the candidate; negative reductions indicate
increased elapsed time. IQRs describe sample spread rather than confidence
intervals.

| Operands / workload | Before ms [IQR] | Candidate ms [IQR] | GNU ms [IQR] | Before reduction % [IQR] | GNU reduction % [IQR] |
| --- | ---: | ---: | ---: | ---: | ---: |
| 512 / siblings | 4.27 [4.20–4.36] | 4.27 [4.24–4.32] | 2.83 [2.80–2.85] | 0.25 [-0.86–2.15] | -50.80 [-53.35–-48.56] |
| 512 / siblings-mode-750 | 4.80 [4.77–4.84] | 4.81 [4.78–4.86] | 4.45 [4.43–4.49] | -0.36 [-1.84–0.37] | -7.99 [-8.93–-6.61] |
| 512 / parents-depth-four | 4.51 [4.45–4.59] | 4.54 [4.50–4.60] | 3.67 [3.64–3.70] | -1.08 [-2.00–0.73] | -23.99 [-24.90–-21.72] |
| 512 / existing-parents | 3.43 [3.40–3.50] | 3.14 [3.11–3.20] | 2.03 [2.02–2.06] | 8.64 [8.02–9.30] | -54.79 [-56.98–-51.86] |
| 4096 / siblings | 16.95 [16.63–17.29] | 16.69 [16.61–17.07] | 14.73 [14.62–14.86] | 0.13 [-0.51–3.56] | -13.97 [-15.70–-12.45] |
| 4096 / siblings-mode-750 | 21.23 [20.91–21.54] | 21.20 [20.79–21.44] | 26.77 [26.59–26.89] | 0.65 [-0.61–1.07] | 20.92 [20.17–21.87] |
| 4096 / parents-depth-four | 18.75 [18.49–18.88] | 18.78 [18.60–19.03] | 20.73 [20.62–20.83] | -0.37 [-1.94–1.59] | 9.43 [7.88–10.83] |
| 4096 / existing-parents | 10.42 [10.05–10.75] | 8.03 [7.69–8.36] | 8.19 [7.92–8.31] | 22.93 [21.64–24.27] | 1.32 [-0.45–2.94] |

Existing-directory handling improves over the baseline by median paired
reductions of 8.6% at 512 operands and 22.9% at 4096 operands. The other
before/after changes are smaller. At 4096 operands, explicit-mode creation and
four-level parent creation have median paired reductions against GNU of 20.9%
and 9.4%. The existing-directory GNU comparison is close, at a 1.3% median
reduction; use the reported spread when assessing that small margin.

GNU has lower elapsed time for every 512-operand workload and for ordinary
sibling creation at 4096 operands. These results preserve the remaining
performance gaps. The narrower relative gaps at larger batch sizes are
consistent with amortizing fixed startup cost; the runs do not isolate its
individual components.

## Syscall validation

A separate trace runs `-p` over 512 existing siblings with the same gutil
options, using `strace -f -c -e trace=mkdir,mkdirat,newfstatat,statx`.

| Executable | `mkdir` calls | `statx` calls | `newfstatat` calls | Traced subset total |
| --- | ---: | ---: | ---: | ---: |
| Baseline | 512 | 512 | 3 | 1027 |
| Candidate | 1 | 512 | 3 | 516 |
| GNU | 512 | 0 | 514 | 1026 |

The candidate avoids 511 failed creation calls and reduces this traced subset
by 49.8%. Metadata is still queried for every operand. Startup metadata calls
are included; this table does not count every process syscall. Trace timings
are excluded from the elapsed-time results.

## Scope and raw samples

The fixtures are empty, warm, memory-backed directories without default ACLs.
No additional `fsync` durability requirement is requested. These results do not
establish physical-storage throughput or performance on Windows or macOS.
Default ACLs, symbolic modes, inherited setgid, ordering, aliases, errors, and
native paths have separate integration coverage. The complete Coreutils
implementation and project-wide performance target remain unfinished.
