# Linux x86-64 filesystem mutation benchmark

Measured on November 18, 2026, in Europe/Istanbul. The comparison uses
GNU Coreutils 9.12 and gutil 0.14.0. The initial gutil revision is
`3e44f47cf1768a8a2007b110a754fe1d8e163e1c`. The optimized Linux binary
is built from `7d6f73b431f1d499db2e537d01d0bcbb29f56725`.

## Machine and tools

| Item | Recorded value |
| --- | --- |
| CPU | Intel Core i5-3210M at 2.50 GHz, 2 physical cores, 4 logical CPUs |
| Available CPUs | All 4 logical CPUs, without isolation |
| Frequency policy | `intel_cpufreq` driver, `schedutil` governor |
| RAM | 7.61 GiB visible to Linux |
| Operating system | Arch Linux, x86-64 |
| Kernel | `7.3.4-zen2-2-zen` |
| Filesystems | ext4 checkout and executable, tmpfs fixtures under `/tmp` |
| Rust toolchain | rustc 1.100.0, Cargo 1.100.0, `x86_64-unknown-linux-gnu` |
| Harness | Criterion 0.8.2, optimized Cargo bench profile |

## Workload and timing

Each measured iteration starts a child, waits for exit, and discards stdout
and stderr. The fixture is created before the measured interval and removed
after it. Every iteration receives a fresh fixture. The process environment
sets `LC_ALL=C` and `TZ=UTC` and removes `VERSION_CONTROL` and
`SIMPLE_BACKUP_SUFFIX`. gutil also receives `--no-config --progress=never
--jobs=1`. Filesystem changes execute in operand order inside one blocking
runtime task.

| Workload | Operands and initial state |
| --- | --- |
| `link` | `source linked`, with a seven-byte source containing `content` |
| `ln` | `source linked`, creating a hard link to the same seven-byte content |
| `unlink` | `source`, initially a seven-byte regular file |
| `rmdir` | 512 distinct empty directories, named `item-0` through `item-511` |
| `truncate`, one file | `-s1024 item-0`, with an existing seven-byte file |
| `truncate`, many files | `-s1024 item-0 ... item-511`, with 512 existing seven-byte files |

Before timing each variant, verification checks its successful exit and
empty stdout. It checks hard-link identity, removal of names or directories,
and resized contents. Truncated files must contain the original seven-byte
prefix followed by zero bytes to a total length of 1,024 bytes.

```sh
TMPDIR=/tmp GNU_COREUTILS_DIR=/usr/bin cargo bench --locked -p gutil --bench mutate -- --noplot
```

Criterion uses 10 samples, a 400 ms warmup, and a one-second measurement
target. The custom timer excludes fixture preparation and cleanup.
Filesystem metadata and executables stay warm through repeated invocation.
The desktop session shares CPU resources with these processes, and CPU
frequency varies.

## Optimized Criterion results

Elapsed-time point estimates and 95% confidence intervals are in milliseconds.

| Workload | gutil | GNU |
| --- | ---: | ---: |
| `link` | 2.137 [2.010–2.245] | 1.073 [1.032–1.129] |
| `ln`, hard link | 2.050 [1.994–2.154] | 0.996 [0.905–1.055] |
| `unlink` | 2.068 [1.963–2.168] | 0.793 [0.767–0.835] |
| `rmdir`, 512 directories | 3.882 [3.795–3.973] | 2.434 [2.372–2.535] |
| `truncate`, one file | 2.076 [1.932–2.172] | 0.844 [0.791–0.909] |
| `truncate`, 512 files | 3.806 [3.775–3.842] | 2.511 [2.384–2.758] |

GNU has lower latency in all six workloads on this machine. gutil's initial
512-file truncation estimate is 4.497 ms [4.299–4.658]. The optimized path
avoids querying target metadata when assigning an absolute length or using
a reference length directly. Relative adjustments and I/O block sizing
still obtain the metadata they require.

## Paired truncation comparison

A Python harness compares saved initial and optimized gutil binaries with
GNU using the same 512-file fixture and arguments. Before each invocation,
it resets every file to seven bytes outside the measured interval. It
verifies all output file contents for each binary before collecting timings.
Four warmup rounds precede 30 measured rounds. Invocation order is shuffled
in each round using Python's random seed 42. Processes use the same C locale,
UTC, and gutil worker/progress settings as the Criterion run.

Values are median elapsed times and interquartile ranges in milliseconds.

| Variant | Median elapsed time | Interquartile range |
| --- | ---: | ---: |
| Initial gutil | 4.296 | 4.252–4.476 |
| gutil with conditional metadata reads | 3.928 | 3.865–4.313 |
| GNU Coreutils 9.12 | 2.427 | 2.384–2.492 |

The optimized gutil binary finishes sooner in 26 of 30 paired rounds.
The median paired elapsed-time reduction is 8.9%, with an interquartile
range of 5.0–10.1%. These measurements apply to the recorded file count,
filesystem, machine, and cache conditions.
