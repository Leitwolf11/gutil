# Linux x86-64 tab expansion

Compare gutil `05be433` with GNU Coreutils 9.12 `expand`. The gutil
release build uses byte-run scanning for single-byte input and the Unicode
column path when UTF-8 input contains multibyte data.

| Item | Environment |
| --- | --- |
| CPU | Intel Core i5-3210M at 2.50 GHz, 2 cores and 4 logical CPUs |
| Affinity | Harness and child processes pinned to logical CPU 3 |
| Memory | 7.61 GiB visible to Linux |
| System | Arch Linux x86-64, kernel 7.3.4-zen2-2-zen |
| Toolchain | rustc 1.100.0 with LLVM 23.1.5, default release profile |
| Storage | Executables on ext4, input and output on tmpfs |

Each workload reads a warm 16,777,200-byte regular file and writes another
regular file. Three cases use tab-delimited ASCII text in the C locale with
default positions, leading tabs only, or custom positions `3,11,+5`. The
fourth uses accented Latin, Japanese, and emoji text in C.UTF-8 at the
default positions. gutil uses `--no-config --progress=never --jobs=1`.

Four warmups precede 12 measured rounds in seeded, interleaved order.
Elapsed time includes startup, reading, expansion, writing, and process
exit. The harness checks empty stderr, successful exit, and the full output
hash on every run. Output hashing happens outside the timed interval.

| Workload | gutil median (ms) | GNU median (ms) | Paired reduction vs. GNU, median [IQR] |
| --- | ---: | ---: | ---: |
| ASCII, default | 86.22 | 407.36 | 78.9% [78.7%, 79.1%] |
| ASCII, initial only | 41.33 | 290.22 | 85.6% [85.2%, 86.0%] |
| ASCII, custom stops | 85.30 | 400.48 | 78.4% [77.9%, 78.7%] |
| UTF-8, default | 133.62 | 306.91 | 56.4% [55.8%, 57.0%] |

Paired median elapsed times were 56–86% lower than GNU's in these
workloads. The report covers warm regular files on the recorded Linux host.
